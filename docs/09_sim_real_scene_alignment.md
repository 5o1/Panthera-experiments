## 2. 哪些必须模仿，哪些应随机化

仿真不需要逐像素复制整个实验室。需要保持的是会改变任务几何或策略可观测性的因素：

- 最终送入 VLA 的相机类型、安装位置、朝向、视场角、分辨率和裁剪方式；
- Panthera 基座、桌面、圆柱和凹槽之间的尺度与相对坐标；
- 圆柱、凹槽和夹爪的碰撞几何、质量、摩擦以及可接受插入间隙；
- 机械臂自身、夹爪和任务物体在策略画面中的遮挡关系；
- 真实控制周期、动作表示、关节零位、夹爪范围和延迟。

不应固定成单一外观的因素应做有边界的域随机化：

- 亮度、色温、轻微阴影和曝光；
- 桌面及物体的合理颜色、纹理变化；
- 不遮挡关键任务区域的背景物和线缆；
- 相机安装误差范围内的小幅外参扰动；
- 传感器噪声、轻微模糊和压缩失真。

随机化不能掩盖错误的任务定义。例如物体尺寸、槽宽或相机主视角明显不符时，增加随机
背景不会解决 sim-to-real 问题。

## 3. 当前相机决定与数据通路

当前没有额外的 VLA 专用相机。项目决定尽可能复用手机 SRT 源，同时作为策略相机和实验
监控相机。手机必须安装在固定支架上；手持、每次重装后位置不一致或自动切换镜头均不满足
策略相机要求。2026-09-12 的归档画面用于设计场景和离线开发，但摄像头已经摘下，因此
不能把该帧当作最终外参标定结果。

`tools/receive_srt_camera.sh` 当前生成的 `latest.jpg` 只有 2 FPS，且 FFmpeg 会重复更新同一
文件。它适合人或 agent 监看，不应被控制环直接轮询。正式 VLA 图像通路应为：

```text
手机 SRT → 连续 FFmpeg 解码 → 内存中的 latest-only 单槽帧
         → 本地接收单调时间戳与帧龄检查 → VLA 预处理/推理
```

推理速度低于视频帧率时覆盖旧帧，不形成 FIFO 图像积压。断流、帧龄超过阈值、时间戳
倒退或解码器退出时，不再产生新动作并锁存为不可执行。原始 SRT 循环录像与实际送入策略
的帧序号/时间戳应同时记录，以便重放和对齐机器人状态。

当前 SRT listener 位于 WSL，而 VLA 位于 Lab。正式在线推理前还需建立一条持久低延迟中继
或让 Lab 直接接收 SRT，并实测端到端帧龄；不能用每帧启动一次 SSH/SCP 的方式传图。

## 4. 监控相机与策略相机的逻辑数据仍要分开

外部相机可能有两种角色：

1. **监控数据**：供操作者或 agent 查看实验台、安全状态和实验结果，可以保留原始宽视角。
2. **策略数据**：由同一 SRT 帧经过固定裁剪、缩放和时间戳检查后送入 VLA；它的内外参、
   构图和遮挡必须成为仿真场景的主要对齐对象。当前近距离仿真画面不能在未标定时直接
   代表真实输入。

同一台相机也可以同时承担两种角色，但数据记录必须明确保存 `policy_rgb` 与
`monitor_rgb` 的来源、时间戳和分辨率，不能把两者混为一种 observation。
