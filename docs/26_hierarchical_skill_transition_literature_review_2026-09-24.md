# Panthera 层级技能转移与释放失败：文献调查

日期：2026-09-24

## 1. 问题和结论

当前单轨迹过拟合闭环反复出现一种失败：策略能夹住圆柱并把它送到槽点上方，但在
轻微偏离专家状态的自主闭环中可能持续保持夹爪闭合。用户提出把任务拆成三个技能：

1. `grasp(object)`：夹住圆柱；
2. `move_held_object(target)`：把已夹持物移动到槽上方；
3. `release(object, target)`：松开夹爪。

低层策略在完成当前技能时提出状态转移，上层编排器检查转移是否合法，合法后才发送下一
技能指令。

文献支持把该方案列为当前最高优先级的对照实验，但不支持在实验前宣称它一定“显著改善”。
它要检验的是**释放阶段条件是否不足以及职责是否混在同一动作回归中**：低层策略不再仅凭
当前观测自行决定何时从搬运切换到释放，而是在明确的 `release` 条件下执行释放技能。现有
相邻帧证据只是连续开爪斜坡跨过人为 0.5 分界，不能证明存在语义相反的监督标签。
它不会自动修复搬运阶段的动作块抖动，而且错误的技能标签或终止判断本身可能产生振荡、
过早切换或停滞。

## 2. 检索范围

只纳入能直接回答下列至少一个问题的原始论文：

- VLA 或模仿学习是否从高层任务先预测子任务，再预测低层动作；
- 长任务能否从弱子任务顺序标注中学习分段；
- 技能是否应具有独立的终止函数；
- 上层规划器如何用当前物理状态约束技能选择；
- 是否存在独立监视器验证技能完成并触发状态转移。

## 3. 逐篇证据

### 3.1 Option-Critic：技能和终止条件是两个对象

Option-Critic 把一个时间延伸动作（option）定义为启动集合、技能内部策略和终止函数三元组
`(I, π, β)`；智能体执行内部策略，直到终止函数触发，之后才重新选择 option。论文证明了
内部策略与终止函数可以共同学习。这为“动作头之外另有 `done`/termination 输出”提供了
正式框架，但其实验是强化学习环境，不是视觉模仿学习，也没有外部几何验证器。因此它只能
证明这种建模合法，不能直接证明 Panthera 的三技能分解有效。

来源：[The Option-Critic Architecture](https://arxiv.org/abs/1609.05140)。

### 3.2 TACO：已有连续轨迹可以按子任务草图学习对齐

TACO 只要求每条示范带有子任务的顺序（task sketch），不要求人工给出每一帧属于哪个子
任务；训练过程同时对齐示范和子任务，并学习各个子策略。它在包括纯图像输入的仿真三维
机械臂任务上进行了验证。

这说明 Panthera 可以先使用 `grasp → move_held_object → release` 作为顺序监督；如果
schema 10 的 oracle 阶段边界可靠，可以直接监督；若边界不可靠，TACO 类时间对齐是备选。
不过 TACO 的规模和模型类型都不同于当前 OpenVLA-OFT，不能把其结果直接外推为成功率。

来源：[TACO, ICML 2018](https://proceedings.mlr.press/v80/shiarlis18a.html)。

### 3.3 SayCan：上层提出技能，物理可供性约束选择

SayCan 为每个候选技能组合两个分数：语言模型判断该技能对总体指令是否有用，技能价值
函数判断它从当前物理状态出发是否可执行。系统选择兼具“有用”和“可执行”的技能，执行
后重新规划，直到选择终止。论文在 101 个真实机器人任务中报告：带可供性约束的系统总体
规划成功率为 84%、执行成功率为 74%；去掉可供性后规划成功率降到 67%。

这支持“上层不能只相信模型的状态转移申请，必须用当前状态验证”，但 SayCan 的可供性是
技能成功概率，不等同于逐帧判定当前技能已经完成。

来源：[Do As I Can, Not As I Say](https://arxiv.org/abs/2204.01691)。

### 3.4 RT-H：中间动作语言能帮助控制，也会引入新的振荡

RT-H 先从图像和任务预测动作语言，再以图像、任务和动作语言预测低层动作。论文报告它在
多任务数据上相对 RT-2 提高 15%，说明中间动作抽象可以缩小低层动作预测问题。但论文也
明确报告：系统性的动作语言预测错误会导致振荡或错误行为，而平面模型未必出现这些问题。

因此层级不是无条件增益。Panthera 若采用三技能分解，必须把“技能转移申请”和“技能转移
批准”分开，并记录技能切换抖动率；否则新的离散边界可能把现有连续动作抖动变成高层状态
振荡。

来源：[RT-H](https://arxiv.org/abs/2403.01823)。

### 3.5 Hi Robot：高层和低层应使用不同频率，但论文实现没有完成检测

Hi Robot 的高层 VLM 从图像和开放式指令生成当前原子语言命令，低层 VLA 根据图像、机器人
状态和该命令生成动作块。高层低频运行，低层高频运行。作者讨论了“检测命令完成后再触发
高层推理”这一方案，但其实际实现是每秒或收到新语言反馈时重新运行高层模型。

因此该论文支持双速率架构，不构成 `done` 驱动切换已经被验证的证据。它还提示 Panthera
不应让昂贵的上层代理参与 50 Hz 控制；上层只应在技能开始、终止申请或异常事件时运行。

来源：[Hi Robot](https://arxiv.org/abs/2502.19417)。

### 3.6 π0.5：同一模型也可以先预测语义子任务，再预测动作

π0.5 在推理时先根据当前场景和长程任务预测语义子任务，再以该子任务为条件生成低层动作
块。消融实验中，完整高低层推理优于不进行高层推理的版本；但只在训练中加入子任务预测
数据、运行时不显式做高层推理的版本也获得了很大一部分收益。

这说明 Panthera 应分别检验两种收益来源：一是阶段标签作为训练辅助监督，二是运行时真的
进行状态切换。π0.5 依赖多机器人、网络数据和大量多场景数据，其结果不能证明单轨迹三技能
模型会自然泛化。

来源：[π0.5](https://arxiv.org/abs/2504.16054)。

### 3.7 Hierarchical Vision-Language Planning：最接近提议的已实现系统

该系统用高层 VLM 规划技能序列，用独立 VLM 监视器约 1 Hz 检查 1.5 秒、10–15 帧的视频
片段，并为当前技能输出二元结果 `completed` 或 `in progress`。技能选择器只在监视器确认
后切换模仿学习策略。真实 Unitree G1 的 40 次 pick-place 实验中完成 29 次，整体成功率
73%。

这是“低层技能 + 外部完成验证 + 上层切换”的最直接证据。但论文同时报告监视器会因细微
几何误差或视觉歧义而过早确认完成；其任务、机器人、双相机和模型均不同于 Panthera。
所以外部验证不是简单添加一个布尔值，而必须有明确前置条件、效果条件和拒绝路径。

来源：[Hierarchical Vision-Language Planning for Multi-Step Humanoid Manipulation](https://arxiv.org/abs/2506.22827)。

### 3.8 为什么持续搬运和末端释放不是同一种控制问题

Panthera 的视频复核给出了一个条件性事实：有效夹持一旦形成，已审阅 rollout 的后续搬运
都能到达槽上方；主要前段失败发生在夹持形成之前，剧烈抖动先撞倒并推离圆柱。末端失败则
发生在正确释放位，策略仍保持约 0.3 的闭合开度。这不能概括为整条轨迹都同样不稳定。

现有研究从不同角度解释了两段的结构差异，但没有论文直接证明 Panthera 的具体因果：

- ContactNets 指出撞击和静摩擦等接触动力学具有不连续性。对本任务而言，持物搬运期间
  保持同一夹持接触模式；释放要求主动破坏该接触并进入自由物体/重力沉降模式。把后者
  当成前者的普通平滑延长缺少接触模式归纳偏置。这是物理结构证据，不是对当前 VLA 的
  直接故障定位。来源：[ContactNets](https://proceedings.mlr.press/v155/pfrommer21a.html)。
- PerAct 明确认为直接预测连续动作低效且噪声大，改为预测瓶颈关键帧，并把夹爪开合单独
  作为动作分量。它说明停点和夹爪状态值得在动作表示中被突出，不应只依赖长轨迹的平均
  回归误差。来源：[PerAct](https://peract.github.io/)。
- CLIPort 把桌面操作直接表示为一系列 pick-and-place affordance；MimicGen 则把长演示
  切成对象中心子任务，并用 termination signal 决定子任务边界。两者都通过动作抽象或
  显式边界避免让一个平面逐帧策略独自发现全部 pick/place 转移。来源：
  [CLIPort](https://proceedings.mlr.press/v164/shridhar22a.html)、
  [MimicGen](https://proceedings.mlr.press/v229/mandlekar23a.html)。
- DAgger 的一般结论是监督数据和策略自己访问的状态分布不同会破坏普通行为克隆。它支持
  “专家帧上会开爪、自主闭环却停在闭合状态”属于分布偏移问题，但没有说明应采用哪种
  释放表示。来源：[DAgger](https://proceedings.mlr.press/v15/ross11a.html)。
- ACT 用动作分块降低有效时域，并用 temporal ensemble 平滑建模误差。论文证明这些机制
  能改善精细操控，但没有证明平均动作块能可靠保留稀少的接触模式转换；Panthera 还必须
  单独报告松爪事件，不能只看轨迹平滑度。来源：
  [ACT](https://tonyzhaozh.github.io/aloha/)。

结合项目证据，当前最窄的解释是：搬运是“夹持模式内”的长而密集的连续控制，圆柱在真实
夹爪接触和摩擦下随末端移动；释放则是稀少的接触模式转换，主要监督变化集中在夹爪一维，
且策略必须先输出开爪才会看到物体脱离后的新观测。如果它持续输出闭合，物理状态和下一帧
观测都继续支持“仍在持物”，形成闭环固定点。最后一句是依据 Panthera trace 和上述研究
作出的项目推断，仍需阶段条件/终止验证消融确认。

## 4. 对 Panthera 的具体设计结论

建议把三个概念分开：

- `skill_command`：上层当前要求执行的通用技能及参数，例如
  `move_held_object(target=slot)`；
- `transition_proposal`：低层根据图像与 proprio 输出当前技能完成的概率或候选事件；
- `transition_verdict`：独立验证器根据技能的前置条件和效果条件输出 `accept/reject/unknown`。

只有 `transition_proposal` 达标且 `transition_verdict=accept` 时才切换。`reject` 继续执行或
进入恢复策略，`unknown` 保持当前技能但设置超时上限。不要把完成标志塞进现有七维动作的
夹爪维，也不要让上层代理每个 50 Hz 控制步重新生成自然语言。

初始技能合同建议保持任务无关语义：

| 当前技能 | 可接受的完成效果 | 下一技能 |
|---|---|---|
| `grasp(object)` | 对象被可靠夹持并随末端运动 | `move_held_object(target)` |
| `move_held_object(target)` | 对象保持夹持且进入目标允许的释放区域 | `release(object, target)` |
| `release(object, target)` | 夹爪开度达到目标且对象不再被夹持 | 任务完成或下一技能 |

在仿真诊断中可以先使用特权物体位姿和接触状态做验证器上界；正式 sim-to-real 结论必须再
用真实部署可获得的视觉、关节、夹爪和力/力矩信号替换，不能把仿真真值验证器的成功率当作
真实方案成功率。

## 5. 最小对照实验

使用相同 episode 2、相同 checkpoint 预算、相同动作执行模式和相同初始场景，依次运行：

1. `Flat`：当前单指令、七维动作基线；
2. `Phase-conditioned + oracle transition`：低层接收三种技能指令，仿真 oracle 决定切换；
3. `Learned proposal + oracle verifier`：学习终止申请，oracle 只验证；
4. `Learned proposal + deployable verifier`：验证器只能使用未来真机可获得的观测。

每组至少分别报告：完整任务成功率、抓取成功率、到达释放区比例、松爪成功率、过早切换率、
拒绝/未知次数、技能切换振荡次数、搬运段动作变化量和策略推理耗时。只有第 2 组相对 Flat
改善，说明阶段条件本身有效；第 3 组再通过，说明终止头可学；第 4 组通过，才说明方案具备
真实迁移价值。

## 6. 当前判断

该方案比继续单纯降低七维回归 loss 更有针对性，值得立即做最小仿真消融。最强证据来自
π0.5 的运行时语义子任务、Option-Critic 的独立终止函数，以及 VLM planner-monitor 系统
的二元完成验证。它针对“不知道现在应保持还是松开”的阶段混叠，而不是把夹爪改成阈值
控制。实验前仍不能承诺显著改善：最相近系统也会因为视觉监视器过早确认而失败，RT-H 也
表明错误的中间层预测可能制造振荡。
